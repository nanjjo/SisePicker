# 고덕그라시움 성능 확인

측정일: 2026-10-15. 대상: https://new.land.naver.com/complexes/113907

## 실제 웹 목록 확인

- 매매·전세, 전체면적·전체동, 낮은가격순, 동일매물 묶기 해제 상태로 확인.
- 지도 표시: 매매 1,014건 + 전세 73건 = 1,087건.
- 마지막까지 로딩된 DOM: 매매 1,014건 + 전세 73건 = 1,087건. 건수 일치.
- 처음 20건에서 End 키로 목록 끝까지 이동하고 건수를 읽는 작업 50회.
- 50회 작업 시간 합계 12,315ms. 도구 호출 사이의 모델 처리/대화 시간, 초기 페이지 및 필터 설정 시간 제외. 즐겨찾기 자체의 수집 완료 시간으로 해석하면 안 됨.
- 일부 작업은 새 목록 도착 전 같은 건수를 읽으며, 일부는 여러 배치가 도착했다. 마지막 작업은 1,539ms.
- 사이트의 안내 팝업은 닫고 진행했다.

## 전체 목록 읽기 확인

현행 naverListings와 같은 네 가지 DOM 필드(거래종류, 가격, 면적/층, 단지명)를 1,087건 읽고 JSON.stringify한 뒤 개수·문자수를 반환했다.

5회 도구 왕복 시간: 310, 32, 32, 33, 52ms. 중앙값33ms. JSON 길이88,762자.
브라우저 내 고해상도 타이머는 도구의 읽기 전용 실행 환경에 제공되지 않아 순수 JavaScript CPU 시간은 측정하지 못했다. 위 수치는 도구 왕복을 포함하며, 파이썬 붙여넣기 및 PPT 생성 시간은 포함하지 않는다.

## 해석과 한계

- 1,000건 이상에서도 웹 목록 전체 로딩과 텍스트 읽기가 가능함을 확인했다.
- 이 측정에서는 한 번의 전체 읽기보다 반복되는 목록 로딩·대기가 큰 비용으로 보인다. 따라서 멀티스레딩보다 불필요한 전체 DOM 재읽기 감소가 우선 개선 후보다.
- 현행 수집기는 목록 안정 여부를 확인할 때 전체 필드를 재추출하고 JSON으로 변환한다. 대규모 단지에서는 이 반복 비용을 줄일 여지가 있다.
- 현행 100회 제한은 20건씩 정상 증가하면 약2,000건 수준을 커버하지만 재시도도 횟수를 사용한다. 1,087건은 통상 약55배치이므로 범위 안에 들어간다. 실제 수집 성공을 보장하는 계산은 아니다.
- 이번 실제 UI 검사는 End 키로 목록을 로딩한 것으로, 즐겨찾기 스크립트 실행→복사→앱 붙여넣기 종단 측정을 대신하지 않는다. 기존 2026-10-13의 1,061건/중단 표본과 오늘 측정치를 합산하지 않았다.
- 프로그램 및 EXE 변경 없음. 성능 근거와 제한을 남기는 검증 작업이다.
